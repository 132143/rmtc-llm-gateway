# 02 · 项目怎么搭起来的（三个盒子 + 代码地图）

> 这一份回答两个问题：**这堆文件是怎么分工的**、**我想改某件事该动哪个文件**。
> 读完你应该能在 30 秒内说出"某个功能在哪个文件里"。

## 一、先看一张图（三个盒子）

```text
                      ┌──────────────────────────────┐
  裁判（ROS 2 话题）  │  盒子② 参赛程序 contestant/  │   动作 JSON
  /team_A/perception │  bot_node.py  ← 只这一层用 rclpy│  /team_A/action
  ─────────────────► │      ↓                        │ ─────────────►
                     │  agent.py  （感知 → 动作）     │
                     └──────────┬───────────────────┘
                                │ 需要理解事件公告时 HTTP 调用
                                ▼
                     ┌──────────────────────────────┐
                     │ 盒子① 官方统一 AI 网关        │──► 大模型（DeepSeek 等）
                     │ 客户端 rmtc_client/ （我们写的）│
                     └──────────────────────────────┘

  盒子③ rmtc_gateway/ = 我们**自己**写的一个同协议网关，只在本地练链路时用
  （正式比赛禁止用它，必须用主办方地址）
```

### 三个盒子分别是什么

| 盒子 | 是什么 | 什么时候跑 | 谁能改 |
|---|---|---|---|
| ① rmtc_client/ | "调 AI"的那半：异步请求、4 秒超时、预算、降级、JSON 修复 | 常驻，跟程序一起跑 | 可以，但要小心 |
| ② contestant/ | "做决定"的那半：收感知、算策略、发动作 | 比赛时唯一要启动的东西 | 我们改得最多 |
| ③ rmtc_gateway/ | 本地网关，用来在没有主办方网关时练链路 | 只在练习时 | 基本不动 |

## 二、代码地图（每个文件一句话）

### 2.1 参赛程序（contestant/）—— 你 90% 的时间会在这里

| 文件 | 行数 | 一句话 | 你会不会动它 |
|---|---|---|---|
| bot_node.py | 236 | ROS 2 节点：订阅感知、发布动作。**唯一依赖 rclpy 的文件** | 基本不动（动了要重测 QoS） |
| agent.py | 1457 | 感知 → 动作的"大脑"：状态闸门、任务、战斗、记忆、AI 结果消费 | 常改（策略在延伸处） |
| strategy.py | 186 | 第一阶段和探索用的 BFS 贪心（"谁近去谁"） | 少改 |
| decision.py | 78 | 决策类型登记表（现场唯一允许改的字符串） | 只有赛前改 |
| tactics.py | 384 | 封存参数 + 五类收益公式（纯函数，好单测） | 调参时改 |
| planner.py | 509 | 收益表决策内核（可选，planner=fused 时才用） | 研究用，平时不动 |
| sim.py | 111 | 第一阶段的本地模拟器（按官方参数） | 不动 |
| stage2_sim.py | 581 | 第二阶段离线仿真器（按规则结算，评测用） | 不动（动了所有实验都要重跑） |
| eval_lab.py | 303 | 对照实验台：分组 × 地图 × 对手 × 重复 | 跑实验时用 |
| events.py | 310 | 事件注入（裁判侧真值 + 自然语言公告） | 不动 |
| llm_replay.py | 172 | 把真实模型的判断录下来离线回放 | 不动 |
| run_experiments.py | 80 | 第一阶段策略对比脚本 | 偶尔用 |
| map_import.py | 210 | **裁判地图编辑器格式**的导入/导出/校验（正式地图与测试完整配置都支持） | 换地图时用 |
| sweeper.py | 200 | **扫图型假想敌**：移动优先 + 扫图 + 拿最近资源 + 躲危险 + 打一下就跑 | 当陪练/压力测试 |

## 三、一帧感知长什么样（真实字段）

```json
{
  "tick": 147,                      // 当前时间片，动作必须原样回填
  "session_id": "match-2026-...",   // 本场编号，动作必须原样回填
  "vision_radius": 4,               // 视野半径（0–4），不要写死
  "self": {"position": [8, 8], "hp": 100, "alive": true, "protected": false,
           "defending": false, "last_action": {"moved": true, "effective_direction": "right"}},
  "visible_entities": [
    {"type": "resource_high", "value": 20, "position": "000000000\n...9 行..."},
    {"type": "obstacle",      "position": "..."},
    {"type": "robot", "hp": 60, "protected": false, "defending": true, "position": "..."}
  ],
  "score": {"resource_value": 40, "effective_damage": 180, "mission_completed": 1,
            "mission_completed_ids": ["collect_two_normal"]},
  "missions": [{"id": "reach_target", "type": "reach", "position": [12, 12]}],
  "map": {"width": 24, "height": 24},
  "event_text": "第 10 Tick：随机事件预告：……"   // 自然语言，只能交给大模型
}
```

要点：**自己的坐标是绝对坐标**，**别人的坐标是一个 9×9 的字符串**（'1' 是自己，'2' 是那个实体）。
解码在 agent.py 的 `decode_relative()`，两行就能看懂。

## 四、一帧动作长什么样（我们能发的全部）

```json
{"tick": 147, "session_id": "match-2026-...", "action": "move",   "direction": "right"}
{"tick": 147, "session_id": "match-2026-...", "action": "attack", "direction": "up"}
{"tick": 147, "session_id": "match-2026-...", "action": "defend"}
{"tick": 147, "session_id": "match-2026-...", "action": "wait"}
```

规则：字段全小写、方向只能是 up/down/left/right、**同一 Tick 只发一条**、
不要"先发一个占位的再改"（后到的合法动作会覆盖前一个候选，改不回来）。

## 五、程序启动时到底发生了什么（顺序很重要）

| 顺序 | 发生什么 | 在哪 |
|---|---|---|
| 1 | 读环境变量（席位、令牌、网关地址） | bot_node.py 的 main() |
| 2 | 建 3 个话题：订阅感知、发布动作、发布队伍名 | bot_node.py 的 RmtcBotNode |
| 3 | 读 decision_config.json（只认 decision_type 一个键） | decision.py |
| 4 | 起一个 AI 客户端（异步，不阻塞） | rmtc_client |
| 5 | 收到第一帧感知 → 建策略对象、清空上一场 | agent.py::on_perception |
| 6 | 每帧：必要时问 AI（事件变化/资格兜底）→ 决策 → 动作 | agent.py::_decide |
| 7 | 看门狗每 2 秒检查"多久没收到感知" | bot_node.py::watchdog |

## 六、想改东西先查这张表（会调会改的快速索引）

| 你想改… | 打开哪个文件 | 找什么 |
|---|---|---|
| 抢资源的先后顺序 | strategy.py | `GreedyBfsStrategy.decide` 里的 `rank()` |
| 什么时候开打 | agent.py | `_decide()` 里 `combat_allowed` 那一段 |
| 任务点优先级 | agent.py | `go_reach_now` 与 reach 分支 |
| 补任务缺失的资源 | agent.py | `_mission_resource_move()` / `_mission_shortfall()` |
| 战争期干什么 | agent.py | `_war_hotspot()` 与 `war_phase` |
| 参数默认值 | agent.py | `AgentConfig.__init__` |
| 现场能切的类型 | decision.py | `DECISION_TYPES` |
| 提示词（问 AI 什么） | rmtc_client/event_understanding.py | `PROMPT_TEMPLATE` |
| AI 调用预算/超时 | rmtc_client/llm_client.py | `ClientConfig` |
| 参数含义与在哪儿生效 | tactics.py | `PARAM_CONSUMPTION` 字典 |

## 七、一页带走

```text
三个盒子：裁判 ⇄ 参赛程序(contestant/) ⇄ 官方 AI 网关(rmtc_client/)
          rmtc_gateway/ 只是本地练链路用，正式比赛不许用

改策略 → agent.py（决策顺序） + strategy.py（资源排序） + decision.py（类型登记）
改参数 → agent.py 的 AgentConfig（默认值） + tactics.py（收益公式参数）
改提示词 → rmtc_client/event_understanding.py 的 PROMPT_TEMPLATE
跑实验 → contestant/eval_lab.py（分组对比，产物在 docs/experiments/）
```
