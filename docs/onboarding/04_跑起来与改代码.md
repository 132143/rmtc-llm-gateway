# 04 · 跑起来与改代码（命令逐段拆 + 10 个常改点 + 报错对照）

> 这一份是「手把手」：每条命令拆开讲它在干什么；每个改动告诉你动哪一行、怎么验证、改坏会怎样。
> 你现在会 ROS 2 和 CMake，Python 有基础——这里不会假设你懂别的东西。

## 一、先跑通本机测试（不需要 ROS、不联网、不花钱）

```bash
cd <仓库目录>
python run_tests.py
```

| 行 | 段 | 意思 |
|---|---|---|
| 1 | cd | 进到仓库根目录（有 run_tests.py 的那一层） |
| 2 | python | 用 Python 跑（Linux 里可能叫 python3） |
| 2 | run_tests.py | 先做全量语法检查，再跑全部单元测试 |

你会看到（结尾）：

```text
语法检查通过（46 个 .py）
Ran 193 tests in 26.0s
OK
```

看到 **OK** 就说明：46 个 Python 文件语法都对、193 个测试全过。这是「没搞坏」的最低标准。

### 只想跑某一类测试

| 命令 | 管什么 |
|---|---|
| python -m unittest tests.test_contestant -v | 感知→动作那一层（最容易踩坑） |
| python -m unittest tests.test_client -v | AI 客户端（超时/坏响应/错误码） |
| python -m unittest tests.test_events_replay -v | 事件、模型回放、任务组合、高层意图 |
| python -m unittest tests.test_robustness -v | 畸形感知、除零（扫描抓出来的真 bug） |

## 二、本机跑「对照实验」（不连裁判，纯离线）

### 2.1 第一阶段策略对比

```bash
python -m contestant.run_experiments --maps 40
```

| 段 | 意思 |
|---|---|
| -m contestant.run_experiments | 跑包里的这个脚本 |
| --maps 40 | 随机生成 40 张等密度地图（官方练习图永远会跑） |

你会看到（节选）：

```text
贪心 BFS detour=0   得分 40.0/40   资源 200/200   撞墙 0
40 张等密度随机地图：平均 33.90/40   最低 12.0   满分 9/40
```

### 2.2 第二阶段离线对照（最重要的一把尺子）

```bash
python -m contestant.eval_lab --groups guarded_hybrid,baseline_hybrid \
    --envs open24,dense24,maze24,practice18 \
    --opponents probe_mid,probe_strong --reps 6 --ticks 500 \
    --out docs/experiments/check
```

| 段 | 意思 |
|---|---|
| --groups | 要比的分组（baseline_hybrid 是原版，guarded_hybrid 是封存版） |
| --envs | 四张地图：开阔 / 障碍多 / 长墙 / 小图 |
| --opponents | 对手强度：弱 / 中 / 农夫（只采集）/ 强（也是我们） |
| --reps 6 | 每种组合重复 6 次（样本越大越可信） |
| --ticks 500 | 每局 500 片（正式节奏） |
| --out | 结果写到哪（生成 lab_summary.md / .json / lab_raw.json） |

跑完你会看到一张表，重点看四列：**均值、最低、前二率、无效动作**。

### 2.3 想让 AI 复现「真实模型判断」（不花钱）

仓库里有 docs/events_cache.json（8 条真实 DeepSeek 输出）。加上这两个参数就能离线跑事件：

```bash
python -m contestant.eval_lab --groups guarded_hybrid --events \
    --hint-cache docs/events_cache.json --envs open24 --reps 2
```

--events 打开事件注入，--hint-cache 让程序用录好的模型输出回答（缓存里没有的公告会按「没有提示」降级，不编造）。

### 2.4 三个「体检」脚本（改完代码建议都跑一遍）

| 命令 | 干什么 | 通过标准 |
|---|---|---|
| python -m scripts.repo_scan | 静态扫描：密钥泄漏、语法、未使用导入、死函数 | 四行全 [OK] |
| python -m scripts.stress_sweep --stage1 40 --stage2 16 --ticks 300 --events-both --junk 1200 | 压力：随机地图、事件开/关、同种子重跑、1200 帧畸形感知 | 末行 [OK] |
| python -m scripts.analyze_lab docs/experiments/check/lab_raw.json guarded_hybrid baseline_hybrid | 成对比较：均值差 + 置信区间 + 符号检验 | 区间不含 0 才算真差异 |

## 三、在虚拟机里跑官方练习裁判（真机链路）

> 前提：虚拟机里已有练习包 ~/rmtc_practice、ROS 2 Humble、我们的仓库副本。

### 3.1 起裁判（比赛环境那一半）

```bash
cd ~/rmtc_practice
./start_referee.sh --stage 1            # 第一阶段：100 片 × 0.1 秒
./start_referee.sh --stage 2 --bots B,C,D --ai-mode real   # 第二阶段 + 陪练 + 真模型
```

| 段 | 意思 |
|---|---|
| cd ~/rmtc_practice | 进练习包目录（里面有 start_referee.sh） |
| --stage 1 | 第一阶段：只有你一台车，只能走/等 |
| --stage 2 | 第二阶段：四队对抗 |
| --bots B,C,D | 让裁判自动带三个陪练车 |
| --ai-mode real | 让裁判的网关转发到真实大模型（需要 PRACTICE_LLM_* 环境变量） |

### 3.2 起我们的车（比赛程序那一半）

```bash
cd <仓库目录>
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=27 ROS_LOCALHOST_ONLY=0 RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export RMTC_SEAT=A RMTC_TEAM_TOKEN=practice-A
export RMTC_AI_URL=http://127.0.0.1:8080/v1/chat/completions
python3 -m contestant.bot_node --seat A --stage 2
```

| 行 | 段 | 意思 |
|---|---|---|
| 2 | source /opt/ros/humble/setup.bash | 打开 ROS 的工具箱（每个新终端都要做） |
| 3 | ROS_DOMAIN_ID | 本场公布的域号；裁判和你在同一个域才看得见彼此 |
| 3 | ROS_LOCALHOST_ONLY=0 | 允许跨机通信（0 = 不限制在本机） |
| 3 | RMW_IMPLEMENTATION | 用哪个 DDS 实现；现场统一写 fastrtps |
| 4 | RMTC_SEAT | 本场席位（A/B/C/D），决定话题名 /team_A/... |
| 4 | RMTC_TEAM_TOKEN | 本场令牌，调 AI 网关用（不要写进代码） |
| 5 | RMTC_AI_URL | 官方网关地址（正式比赛必须换成主办方给的那个） |
| 6 | --seat A --stage 2 | 席位与阶段；第一阶段把 2 换成 1 |

### 3.3 开局：两步，少一步都不跑

```bash
curl -s -X POST http://127.0.0.1:8080/api/start  -H 'Content-Type: application/json' -d '{"stage":2}'
curl -s -X POST http://127.0.0.1:8080/api/resume -H 'Content-Type: application/json' -d '{}'
curl -s http://127.0.0.1:8080/api/state | python3 -m json.tool | head -40
```

| 调用 | 干什么 | 忘了会怎样 |
|---|---|---|
| /api/start | 部署本场配置（此时还在**暂停**状态） | 什么都没发生 |
| /api/resume | 真正开始计时 | 一直停在暂停态，你会以为程序没连上 |
| /api/state | 看当前 tick、比分、AI 调用统计 | 只能靠猜 |

### 3.4 想加速练习（不用等 4 分 10 秒）

```bash
curl -s -X POST http://127.0.0.1:8080/api/start -H 'Content-Type: application/json' \
  -d '{"stage":2,"tick_ms":100,"max_ticks":200,"bots":["B","C","D"]}'
```

tick_ms 是每片多少毫秒，max_ticks 是总片数。注意：加速只影响练习，正式比赛固定 500 × 500 ms。

## 四、会调会改：10 个最常改的地方

> 每个改动都按「在哪 → 改什么 → 怎么验证 → 改坏会怎样」写。
> ⚠️ 赛前封存后，现场**只允许**改第 1 条（decision_config.json 里的一个字符串），其余都算违规改代码。

### 改 1：换决策类型（现场唯一合法操作）

| 项 | 内容 |
|---|---|
| 在哪 | 仓库根目录的 decision_config.json |
| 改什么 | 只改一个值：{"decision_type": "balanced"} → economy / pressure / turtle / center_grab |
| 怎么验证 | 启动日志会打印「决策类型：xxx（…）→ strategy=…, combat=…」 |
| 改坏会怎样 | 写了没登记的字符串 → 程序回退默认值并记 ERROR（不会崩） |

四个类型的区别（现场选哪个看这张表）：

| 类型 | 干什么 | 什么时候选 |
|---|---|---|
| economy | 只在顺路/拦截位置出手，资源优先 | 正常场次 |
| pressure | 没资源时主动找人打 | 落后、需要拉高上限 |
| turtle | 只补刀残血，脱战阈值提高 | 被针对、血常年低 |
| center_grab | 堡垒/治疗点加权，绑定中心 | 公告了无双堡垒/中心治疗点 |

### 改 2：改战斗纪律

| 项 | 内容 |
|---|---|
| 在哪 | contestant/agent.py 的 AgentConfig.__init__ 里 combat_mode |
| 可选值 | never（完全不打）/ opportunistic（进射程就打）/ finish（只补刀）/ hybrid（没资源时找人）/ evaluate（收益表门控）/ aggressive（主动靠近） |
| 怎么验证 | 跑 eval_lab 两组对照（--reps 3），看「伤害」和「前二率」两列 |
| 改坏会怎样 | aggressive 实测更差（42.5 < 45.0）；evaluate 会几乎不打（26 分档），别当默认 |

### 改 3：改去任务点的时机

| 项 | 内容 |
|---|---|
| 在哪 | agent.py 的 reach_after_tick（默认 250） |
| 改什么 | 调小 = 更早专程去；调大 = 更晚 |
| 怎么验证 | 看实验表的「任务」列和「最低分」 |
| 改坏会怎样 | 太早（比如 60）会为 5 分跑半张图，资源被抢光（实测掉到 3 分档） |

### 改 4：改防御阈值

| 项 | 内容 |
|---|---|
| 在哪 | agent.py 的 low_hp（默认 30） |
| 怎么验证 | 看实验表的「死亡」列与「伤害」列 |
| 改坏会怎样 | 调太高（比如 60）→ 频繁防御 → 输出伤害暴跌（历史 bug：连防 251 帧） |

### 改 5：改抢资源的先后顺序

| 项 | 内容 |
|---|---|
| 在哪 | contestant/strategy.py 的 GreedyBfsStrategy.decide() 里 rank()；以及 agent.py 的 strategy_detour |
| 公式 | priority = 价值 / (距离 + detour) |
| 怎么验证 | 第一阶段跑 run_experiments；第二阶段跑 eval_lab |
| 改坏会怎样 | 写成「价值 × 常数 / 距离」→ 排序不变（乘常数不改顺序），你会以为改了但没变 |

### 改 6：改补任务资源的搜索半径

| 项 | 内容 |
|---|---|
| 在哪 | agent.py 的 mission_max_distance（默认 8）；后半程自动 +6/+4 |
| 怎么验证 | python -m scripts.loss_report ... 看 P(少完成一项) |
| 改坏会怎样 | 实测 8/12/16 三档**完全同分**——能看见的资源都在视野内，放宽半径没有作用对象 |

### 改 7：改 AI 调用的预算 / 间隔 / 超时

| 项 | 内容 |
|---|---|
| 在哪 | contestant/bot_node.py 里 LlmGatewayClient(ClientConfig(...))；默认值在 rmtc_client/llm_client.py 的 ClientConfig |
| 关键字段 | max_calls（预算）、min_interval_s（最小间隔）、timeout_s（超时） |
| 怎么验证 | 真机跑一局，看裁判 ai.A.attempt_count / success_count |
| 改坏会怎样 | 间隔太大会错过事件（事件只活 10~16 片）；超时与失败**也吃额度**，预算按「发出的请求」算 |

### 改 8：改提示词（问 AI 什么）

| 项 | 内容 |
|---|---|
| 在哪 | rmtc_client/event_understanding.py 的 PROMPT_TEMPLATE |
| 铁律 | 提示词里**必须出现 JSON 这个词**（DeepSeek 的 json_object 模式要求，否则 400 → 整场 AI 资格作废） |
| 怎么验证 | python -m unittest tests.test_client -v；真机看 success_count ≥ 1 |
| 改坏会怎样 | 模型可能返回别的格式 → 解析失败 → 事件当没看见（不会崩，但白丢信息） |

### 改 9：改战争期的巡逻点

| 项 | 内容 |
|---|---|
| 在哪 | agent.py 的 _war_hotspot()（中心 + 四角，按 tick/40 轮换） |
| 怎么验证 | 实验表里的「伤害」和「撞墙」 |
| 改坏会怎样 | 只蹲中心更差（31.53 < 34.19）；往「最远未探明区」跑最差（丢任务 34%→47%） |

### 改 10：临时关掉某一处增量（回滚用）

| 想关掉 | 参数（都在 AgentConfig） | 默认 | 关掉的含义 |
|---|---|---|---|
| 资源记忆证伪 | memory_falsify=False | 跟随内核（guarded 默认开） | 回到「永远记住」，会追幻影 |
| 障碍过期 | obstacle_ttl=100000 | 40 | 临时墙变永久障碍（撞墙暴涨） |
| 任务组合约束 | mission_portfolio=False | True | 回到「第一个未完成任务」的老逻辑 |
| 封顶感知 | planner 改 legacy（整体回原版） | guarded | 打到 1200 伤害也不让路 |

## 五、报错对照表

### 5.1 动作被拒（裁判回执里的 error）

| 你看到 | 真实原因 | 怎么办 |
|---|---|---|
| E_PARSE | 发出的不是合法 JSON | 检查序列化（别手拼字符串） |
| E_SCHEMA | 缺字段 / 类型错 / 动作或方向非法 | 字段名全小写，动作只能是那四个 |
| E_TICK | tick 不是当前窗口的 | 必须用当前这一帧感知里的 tick |
| E_SESSION | 缺 session_id 或与当前场次不一致 | 换场后必须用新 session_id |
| E_STATE | 阵亡/保护期/阶段不允许这个动作 | 状态闸门（死了只能 wait、保护期不能打） |
| E_RATE | 单条动作超过 4096 字节 | 别塞额外字段 |
| E_OOB | 移动越界 | 寻路要判边界 |
| E_BLOCKED | 障碍 / 别的车占位 / 争格失败 | **不计无效动作**，但白费一片；我们记成「临时堵塞 8 片」 |

### 5.2 网关错误（HTTP + code）

| 你看到 | 真实原因 | 怎么办 |
|---|---|---|
| 401 missing_token | 没带 Authorization | 检查令牌注入 |
| 401 invalid_token | 令牌无效/被吊销 | 立即报告裁判并留证据 |
| 404 not_found | 路径写错 | 必须是 /v1/chat/completions |
| 413 payload_too_large | 请求体 > 2 MiB | 精简提示词 |
| 429 quota_exceeded | 额度用尽 | 程序已永久降级（继续本地策略），报裁判 |
| 429 rate_limit / concurrency_limit | 太快/并发超限 | 退避重试（并发 ≤2） |
| 501 unsupported_transfer_encoding | 用了 Transfer-Encoding | 改用 Content-Length |
| 502 upstream_unavailable | 连不上上游模型 | 本地降级继续 |
| 504 upstream_timeout | 上游超时（30 秒） | 本地降级继续 |
| 503 audit_unavailable | 无法确认调用记录 | 保持本地决策 + 报裁判 |
| 400 且提到 json_object | 提示词里没有 JSON 这个词 | 程序会自动关 json 模式重试一次；别删提示词里的 JSON |

### 5.3 命令 / 环境报错

| 你看到 | 真实原因 | 怎么办 |
|---|---|---|
| ModuleNotFoundError: contestant | 不在仓库根目录 | cd 到有 contestant/ 的那一层再跑 |
| ModuleNotFoundError: rclpy | 没 source ROS | source /opt/ros/humble/setup.bash |
| [WARN] 5 秒没收到任何感知 | 域号/席位/QoS 不对，或裁判没开局 | 先确认 /api/start 返回 ok，再查 ROS_DOMAIN_ID 与 RMTC_SEAT |
| 程序跑着但比分为 0 | 晚启动（资源被抢光）或没拿到 AI 资格 | 开局前起进程；看 ai.A.success_count |
| 端口 8080 被占 | 上一次的裁判没退 | pkill -f practice.py 后重起（别在跑批时执行） |
| Windows 控制台编码错（GBK） | 中文/符号在 GBK 下打印不了 | 我们的脚本已强制 UTF-8；自定义脚本加 sys.stdout.reconfigure(encoding=utf-8) |
