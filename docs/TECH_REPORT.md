## 一、整体设计

我们把比赛拆成三块，互不耦合：

1. **通信与合规层**（`contestant/agent.py` + `contestant/bot_node.py`）
   - 订阅 `/team_X/perception`、发布 `/team_X/action`，QoS 按协议 §2 固定为 RELIABLE + VOLATILE + KEEP_LAST(1)；
   - 动作原样回填 `tick` 与 `session_id`；同 Tick 重发不重复决策；换场次清空全部缓存；
   - 阵亡只 WAIT、出生保护不攻击、攻击只打直线 1~2 格（规则 §6）。
2. **决策层**（`contestant/strategy.py` + `contestant/agent.py`）
   - 走位：BFS 最短路径 + 资源记忆 + 障碍学习（`E_BLOCKED` 回灌）；
   - 战斗：`hybrid`——顺路打，资源抢完/看不见时主动找人；
   - 任务：未完成的资源任务优先（带 8 格距离门限），后半程去任务坐标。
3. **AI 接入层**（`rmtc_client/`）
   - 只走主办方统一网关（OpenAI 兼容），异步调用、4 秒超时、预算按"发出的请求"计（超时也吃额度）；
   - 模型输出只用于三件事：危险区域规避、幻术方向反转、增益区（"天下无双"堡垒）占领；
   - 输出必须是 JSON，解析失败有 6 类修复策略，仍失败就降级为"没有提示"。

**现场唯一可切换的东西**是 `decision_config.json` 的 `decision_type`（`collect` / `balanced` / `combat`），
符合规则 §2.3。

## 五、遇到的问题与解决思路（真实例子，可直接用）

| 现象 | 根因 | 解决 |
|---|---|---|
| 第一阶段只有 8 分（模拟器里满分） | 给策略的"已探索格子"永远是空集，探索退化成原地乱走；撞墙回执没回灌 | 按视野窗口维护 `explored`；把 `E_BLOCKED` 记成障碍 |
| 第二阶段有 415/500 Tick 在 WAIT | 资源在第 52 Tick 就被四队分完，程序认为"没事可做" | 引入 `hybrid`：没资源可捡时转为压制对手 |
| 事件规避明明写了却从不触发 | 调用间隔 2 秒 > 事件窗口 10~16 Tick | 间隔降到 0.8 秒、预算提到 90、短时危险也躲 |
| 预算 60 次却打了 63 次 | 只在"成功"后计数，多线程同时通过检查 | 准入即占位，按"发出的请求"计数（超时也吃额度） |
| 24×24 上任务只完成 2/3 | 为 5 分任务跑半张图，拖慢开局 | 任务资源加 8 格距离门限：资源 60→90、分数 45→52.5 |
| 练习分数比正式规则算的高 | 练习裁判按 v1.0（伤害 300 封顶），规则 v1.1 是 500 | 一律按 v1.1 换算后再评估 |
