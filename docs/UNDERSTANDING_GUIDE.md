# 看懂版：这套东西到底是什么、为什么这么做

> 写给"没时间看 2000 行代码、但要在答辩和现场不出错"的人。
> 读完你应该能回答三件事：**它在每个 Tick 干什么**、**为什么这么设计**、**哪里可能出问题**。

---

## 一、比赛在考什么（一句话）

一个 24×24 的格子战场，四辆战车同时抢资源、打人、做任务，**100 片（第一阶段）或 500 片（第二阶段）结算一次分数**。
所有判定都落在"**这一片你的动作合不合法**"上，而随机事件只给一段**自然语言公告**——必须用大模型读懂它。

计分只认三样东西（规则 §10）：

```text
资源分  30 × min(资源价值 / 120, 1)      # 捡到 120 价值就满，多捡不加分
伤害分  15 × min(有效伤害 / 500, 1)      # 打到 500 就满，再打也不加
任务分   5 × 完成任务数（最多 3 个）      # 前提：本场至少成功调用过一次 AI
死亡    每死一次扣 60 有效伤害（扣到 0 为止）
```

**这张表决定了我们 80% 的策略**：

| 规则事实 | 我们的选择 | 为什么 |
|---|---|---|
| 资源 120 封顶 | 达标就转去打架/做任务，不再满地图捡 | 多捡是 0 收益，还占 Tick |
| 伤害 500 封顶 | 不追着残血车跑（追人方案实测 −2.1 分） | 打满就够，别为"看起来凶"浪费移动 |
| 任务分要 ≥1 次真实 AI 调用 | **开局第 3 片就主动问一次模型** | 万一整场没有公告，这 15 分就没了 |
| 死亡扣 60 伤害，很贵 | 血少时不硬刚（但"低血撤退"实测是负收益） | 数据说明：撤退反而少打伤害、更容易被打死 |

## 二、每个 Tick 我们的程序在干什么（5 步）

感知从 /team_A/perception 进来（JSON）→ 我们必须在**这一片之内**把动作发到 /team_A/action。

```text
① 解析感知      把 9×9 的相对位置串还原成坐标；记住见过的资源和敌人（记忆会过期）
② 读事件/任务    现在有没有爆炸/幻术/无双…；任务做到哪一步
③ 问 AI（可选）  只有"公告变了"或"还没成功过"才问，一次约 1 秒，异步，绝不阻塞决策
④ 决策          选目标（资源/任务点/敌人/巡逻）→ BFS 下一步 → 输出 move/attack/defend/wait
⑤ 回填          把这一片的 tick 和 session_id 原样写进动作（写错就是 E_TICK，整片作废）
```

**关键设计：AI 是"锦上添花"，不是"必需路径"。** 决策 P99 ≈ 1 ms，模型慢 1 秒也不影响发动作——
请求异步发出，结果到了下一片用，没到就继续按本地策略走。这就是 500 片零无效动作的原因。

## 三、八种随机事件：怎么"读懂"而不"作弊"

规则禁止用关键词硬解析公告（必须走大模型）。所以我们的做法是：

```text
公告文本 ──► Prompt（含座位、当前坐标、地图尺寸、任务）──► 模型
                                                            │
      {"danger_zone": [[3,3],[7,7]], "avoid_until_tick": 15,
       "buff_zone": [[11,11],[13,13]], "mode": "normal", "hint": "…"}
                                                            │
                                                            ▼
      只当成"一块要避开的区域 + 一条自然语言建议"；坐标越界/格式不对就整条丢掉
```

| 事件 | 我们用它做什么 |
|---|---|
| 爆炸（80 伤害/1 片） | 矩形标成危险区，路径绕开 |
| 幻术（移动上下/左右互换 5 片） | 模型判断要不要反转；反转只在 move 出口做一次（攻击方向不反转） |
| 天使（治疗/加护） | 顺路就去 |
| 无双堡垒（3×3、50 片、驻留 10 片给增益） | 用模型给的 buff_zone 当目标点；公告没坐标就忽略，不猜 |
| 世界分裂（十字障碍 + 线上战车阵亡复活） | 阵亡期间只发 wait（规则要求），复活后继续 |
| 辣椒（50 伤害） | 同上，当危险区 |
| 洁身自好（不能攻击） | 切成纯采集 |
| 潘潘（护盾/减伤） | 提高接战意愿 |

**两条铁律**：模型只给"区域 + 建议"，**不发动作**；模型说要往哪走，也要经过 BFS 与边界检查才落地。

## 四、AI 怎么接才不违规、不断线

主办方口径（2026-10-28 答疑）与我们的对应做法：

| 官方说法 | 我们的做法 | 踩过的坑 |
|---|---|---|
| 网关是唯一合法 AI 通道，每席位 100 次/场 | 客户端自设 90 上限，实测用 55~59 次 | 早期按 200 次设计，超配额会被拒 |
| 思考模式默认开，关掉只要 0.78–0.99 s | 请求体带 thinking={"type":"disabled"} | 不关的话单次 8–20 s，动作窗直接爆 |
| max_tokens 建议 512–1024 | 默认 512 | 早期 200 会截断 avoid_cells，解析失败 |
| **不得自己填 model**，由裁判注入统一模型 | 请求体里没有 model 字段 | 填了会被拒/审计不过 |
| 字段不保证全支持（无白名单） | 被 400 拒时 thinking → response_format → 其它 逐级降级重试，最多 3 次 | 硬编码一个字段会在现场直接 0 分 |
| 公告话题 /referee/event_text 逐条发；感知里的 event_text 只是"近期" | **两路都收**：话题按行缓冲 + 感知文本合并去重 | 只吃感知时，晚 join 可能一条公告都看不到 → 一次 AI 都调不到 → 任务分 0 |

## 五、量过的东西（这些数字要能背下来）

### 5.1 对等对手（四辆一模一样的车）：**42.5 分，四席位打平**

| 场景 | 结果 |
|---|---|
| 官方 18×18 图，四席位都是我们 | 全部 42.5（资源 50 / 伤害封顶 / 任务 3/3 / 无效 0） |
| 官方 24×24 图，同上 | 全部 42.5 |
| 24×24 + 裁判自带 8 条官方事件 + 官方模型 deepseek-flash | 全部 42.5，AI 55~59 次**零失败** |

**为什么恰好 42.5**：12.5（资源 50/120）+ 15（伤害过 500 封顶）+ 15（3 个任务）。四辆一样的车，资源必然平分。

### 5.2 我们自己的合成图（更卷）：38 分左右，最低 30

那是"资源更稀疏 + 有障碍"的极限测试，**不是赛场预期**。

### 5.3 被数据否掉的方案（答辩最容易被追问）

| 想法 | 直觉上 | 实测 | 结论 |
|---|---|---|---|
| 低血撤退、不接战 | 少死就是赚 | D 中位数 850→600，"打不满"的局 9→18 | 否 |
| 追着残血车打 | 收人头 | −2.1 分（追击浪费 Tick，还被反打） | 否 |
| 纯收益表交战（不分局势） | 简单可控 | −1.7 分 | 否 |
| 开局静默攒资源 | 稳 | −0.9 分 | 否 |
| **中心偏置 + 经济窗口** | 抢中心资源 | **+3.30 分（CI +1.73~+4.87），最低分 18.9→22.5** | 已采纳 |
| **空闲巡逻**（没事不原地等） | 看不出收益 | 最低分 26.5→**30.0**，且不再"看起来卡死" | 已采纳 |

一句话方法论：**只看均值的改法全部被否，能抬"下限"的改法才被采纳。**

## 六、现场 6 个真实故障点

| 症状 | 原因 | 处理 |
|---|---|---|
| 程序起不来，报"需要 ROS 2" | 忘了 source /opt/ros/humble/setup.bash | 先 source 再跑 |
| Tick 一直是 0 | 域号/令牌不一致，感知根本没到 | 跑 preflight，检查 ROS_DOMAIN_ID 与席位令牌 |
| 动作发了但"执行 Tick"不动 | 动作被拒（E_TICK / E_BLOCKED / E_RATE） | 看裁判端 invalid 计数；trace_view 回放定位 |
| AI 全失败 | 网关地址/token 错，或多队抢配额被限流 | 先跑 preflight（里面有一次真实调用） |
| 分数看着很低 | 练习端是 300 口径 | 用 rescore 换算成 500 口径再判断 |
| 陪练不动 / 不参赛 | --bots 只是登记，不会替你启动机器人 | 三个席位各起 start_bot.sh B/C/D |

## 七、一句话版总结（答辩开场可以用）

> "我们把比赛拆成三个可量化的部分：资源分、伤害分、任务分。资源 120 封顶、伤害 500 封顶，
> 所以我们尽快达标、然后转去抢任务点；任务分要求至少一次真实 AI 调用，所以开局主动问一次；
> 事件必须靠大模型读文本，我们把它降级成"一块要避开的矩形 + 一条建议"，模型永远不直接发动作。
> 所有改动都先在离线台跑 96 局/组、看下限和低分概率，能抬下限的才采纳——
> 最终对等对手（四辆一样的车）在官方尺寸下稳定 42.5 分、零无效动作、AI 零失败。"

## 八、名词小抄

| 词 | 意思 |
|---|---|
| Tick / 片 | 最小时间单位（第二阶段 500 ms 一片） |
| 有效伤害 | 打掉的 HP；死亡扣的是 60 点这个数，不是分 |
| decision_type | 现场可切的决策类型（≤2 次/场、要裁判批准），实现了 6 类 + 3 个兼容别名 |
| event_text | 公告文本（感知里是"近期"，/referee/event_text 是逐条） |
| buff_zone | 无双堡垒的 3×3 区域（以公告为准，不写死） |
| E_TICK / E_BLOCKED / E_RATE | 动作被拒的三种最常见原因 |
| 镜像对局 | 四个席位都用我们自己的程序（量"对等对手能拿多少分"） |
